# 基于 Android Jetpack 的本地化个人记账应用的设计与实现

> 记一笔（MoneyBook）软件设计说明书 / 技术架构论证 ｜ 文档版本 v2.1 ｜ 对应软件版本 v2.1.21（最新发布版） ｜ 代码仓库：https://github.com/liaoyllv/moneybook

## 摘要

在移动互联网时代，个人日常消费呈现高频、分散、多支付渠道的特征。市面主流云记账应用大多捆绑庞大的商业广告、理财推送及强制账号注册，存在严峻的隐私泄露隐患与臃肿的交互层级。针对上述痛点，本文设计并实现了一款**纯粹本地化、零网络权限、以单屏操作哲学为核心**的 Android 记账应用「记一笔」（MoneyBook）。

系统采用 Kotlin 语言与 Jetpack Compose 声明式 UI 框架构建，遵循响应式 MVVM + Repository 架构。在 **v2.1.21** 版本中，系统进行了全方位的工程与交互革新：
1. **首页与账单深度整合**：打破传统多级 Tab 壁垒，将月度宏观统计、预算进度卡片与多维度账单明细列表高度聚合，底栏收敛为首页、统计、设置 3 Tab 紧凑导航；
2. **极速记账与高频优化**：记一笔页面采用 3x4 紧凑网格布局，基于频次权重自适应前置常用分类；引入行末即时联想标签输入引擎，支持多标签归属并保留自由文本备注；
3. **全局顶部浮动胶囊通知（TopSnackbarHost）**：重构操作反馈链路，将通知置于状态栏下方，彻底根除移动端底部软键盘遮挡反馈信息的系统级痛点；
4. **统计四维穿透与单屏自适应呈现**：日期筛选全局置顶，支持占比（Donut 环形图与展开明细）、对比（120dp 铺满对称柱状图）、趋势（110dp 压缩折线图与 KPI）及日历（星期置顶与月度概览下移）等维度，实现全单屏无滑动沉浸式分析；
5. **多模态交互反馈**：基于 SoundPool 44.1kHz 实现物理级清脆按键音效，配合短促触感震动，赋予定制级跟手体验；
6. **无缝数据迁移与分类合并**：支持外部记账数据（如鲨鱼记账等）一键解析导入，实现两类分类合并与预算智能累加。

经物理真机实测与真实 SQLite 迁移断言验证，系统在保障数据绝对私密安全的前提下，显著降低了记账心智负担与操作耗时，具备高度的工程可用性与参考价值。

**关键词**：Android；Jetpack Compose；MVVM；Room；本地记账；单屏操作；数据安全；SoundPool

## 1. 绪论

### 1.1 研究背景与动机
随着移动支付的普及，用户的记账需求从“记录复杂借贷”逐渐演变为“小额、快速、高频记录与支出偏好洞察”。然而，现行主流商业记账软件普遍存在三方面弊端：
- **隐私边界模糊**：强制绑定手机号与云同步，用户核心资产与消费轨迹暴露于第三方服务器；
- **视觉噪音与广告干扰**：开屏广告、横幅弹窗及金融理财导流严重干扰记账流程；
- **交互路径冗长**：从打开应用到完成记账往往需要跨越 3-4 个层级，难以维持记账习惯。

因此，研发一款纯粹单机离线、无广告、操作利落且兼顾深层财务洞察的记账工具具有强烈的现实需求。

### 1.2 核心设计哲学
- **绝对隐私（Zero-Network）**：未声明 INTERNET 权限，代码层无任何外部通信逻辑；
- **单屏操作（Zero-Scroll Core）**：拒绝无意义的信息拖沓，核心记账、宏观首页、统计四维图表均能在单屏视口内一览无余；
- **即时反馈（Multi-Modal Feedback）**：清脆声效与触感震动赋予数字界面以物理实物般的敲击手感；
- **精细洞察（Deep Spending Insights）**：穿透分类表象，结合标签细分统计与 IQR 异常消费挖掘，真正辅助个人开销优化。

## 2. 系统核心架构设计

### 2.1 MVVM 分层与单向数据流
系统严格采用 Google 推荐的现代 Android 架构指南：
- **UI 状态层（State Layer）**：由纯 Compose 声明式组件构成，无状态逻辑，仅观察 ViewModel 暴露的不可变 `StateFlow<UiState>`，用户交互经 Lambda 函数回传为具体意图（Intent/Event）；
- **视图模型层（ViewModel Layer）**：使用 `viewModelScope` 协程生命周期管理异步流计算，使用 `combine` 与 `stateIn` 操作符对数据库多表数据流进行响应式编排；
- **仓库业务层（Repository Layer）**：封装数据来源（Room DAO、DataStore），统一控制业务事务边界（`withTransaction`），确保分类合并、周期账单补记、外部数据导入的原子性；
- **持久化层（Local Storage）**：采用 Room 2.6.1 处理结构化财务关系数据，采用 DataStore Preferences 管理主题、音效、生物识别等偏好配置。

### 2.2 核心模块演进与重构（v2.1.21）

#### 2.2.1 首页与账单深度融合设计
传统架构中首页概览与账单列表分立在两个独立导航 Tab，导致用户在“查看月度大盘”与“核对单笔账单”之间频繁切换。v2.1.21 采用深度合并方案：
- 顶部展示结余卡片与月度预算进度条；
- 中部无缝嵌入搜索框与分类/账户/金额筛选胶囊；
- 下部直接呈现按月吸顶分组的账单明细列表，缩略图置左、金额严格右对齐；
- 底部导航精简为 3 Tab（首页、统计、设置），彻底消除加号位移跳动与过度动画。

#### 2.2.2 全局顶部浮动胶囊通知（TopSnackbarHost）
移动应用中普遍存在输入法弹出时遮挡操作反馈（如“预算已保存”、“记账成功”）的痛点。本系统设计了沉浸式状态栏下悬浮胶囊：
- 状态由全局 `TopSnackbarManager` 单例驱动，解耦具体页面的 Scaffold 依赖；
- 胶囊采用半透明高斯模糊背景与柔和圆角，在状态栏正下方 16dp 处优雅滑入，绝不被任何键盘、软输入法或底部面板遮挡。

#### 2.2.3 记一笔分类高频排序与标签即时联想
- **3x4 紧凑网格**：单屏完整陈列 11 个分类 + 1 个「展开分类」按钮，分类采用加权使用频次自动前置；
- **行末智能联想标签**：标签输入框直接集成在第二排行末，输入过程动态匹配历史标签池，回车即确认新标签，并支持多选与自由文本备注共存。

#### 2.2.4 统计中心单屏化与四维穿透
针对小屏与大字号屏幕容易超出视口的问题，对统计中心进行了系统性几何重构：
- **日期选择器置顶**：为所有 Tab 提供全局时间窗口基准；
- **四维 Tab 紧凑切换**：切换时间跨度（日/周/月/年）严格保持当前 Tab，消除页面跳动；
- **尺寸自适应约束**：占比 Donut 环形图居左并固定明细高度（超出展开）、对比双向柱状图固定 120dp 铺满、趋势折线图压缩至 110dp 并辅以 3 大 KPI 卡片、日历星期置顶且月度概览移至下方，达成真正的单屏自适应。

## 3. 关键算法与机制实现

### 3.1 外部数据（鲨鱼记账等）解析与映射算法
1. 基于标准流式解析器读取 CSV 文件，逐行提取记账类型、时间戳、金额、分类、账户及备注字段；
2. 建立智能映射词典：若本地已存在同名分类则直接关联，若不存在则在当前账本下自动补全创建该分类并赋予对应 Emoji 图标；
3. 将浮点型金额精准转换为以「分」为单位的 64 位整数，并在单数据库事务内批量执行插入，保证数千笔历史账单在 1-2 秒内无损落盘。

### 3.2 分类合并与同月预算累加处理
在分类合并操作中，系统需维护数据一致性与财务预算的合理性：
$$	ext{Budget}_{	ext{target}}(Y, M) = 	ext{Budget}_{	ext{target}}(Y, M) + 	ext{Budget}_{	ext{source}}(Y, M)$$
通过数据库事务原子执行：
1. 批量重定向账单外键：`UPDATE bills SET categoryId = :targetId WHERE categoryId = :sourceId`；
2. 合并对应月份的分类预算记录并删除源分类预算；
3. 级联移除源分类，并通过 `TopSnackbarHost` 给予全局反馈。

### 3.3 IQR 异常支出挖掘与消费偏好模型
为辅助用户优化开销结构，系统在统计层引入基于 IQR（Interquartile Range）的异常支出候选检测：
$$IQR = Q_3 - Q_1$$
$$	ext{Threshold}_{	ext{outlier}} = Q_3 + 1.5 	imes IQR$$
对于超出阈值的单笔支出标记为异常候选，并在统计面板中对比该分类的历史中位数，提示用户关注大额支出。

## 4. 结论与工程展望

本文详细论述了「记一笔」（MoneyBook v2.1.21）的设计思想与实现方案。通过技术重构与交互打磨，应用实现了零网络权限下的极致纯粹记账体验。首页账单融合、单屏四维统计、顶部浮动胶囊通知以及声效触感系统显著提升了操作效率与跟手度。项目所有代码与文档均遵循 MIT 开源协议开放，为本地化 Android 应用的架构设计提供了优秀的实践范本。
